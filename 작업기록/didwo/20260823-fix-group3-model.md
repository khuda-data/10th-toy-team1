# 2026-08-23 모델링 그룹3(교육·법률) 필터 버그 확인 및 수정 결과 푸시

## 1. 내가 준 지침 (프롬프트 요지)
- `local_dataset.parquet` 파일이 6개 직군으로 제대로 필터링되었는지 확인 요청.
- 그룹1(경영)과 그룹3(교육)의 Test 대상자(SAMPID)가 154명으로 완벽히 겹치는 문제 파악 및 원인 분석.
- 다른 그룹(1~6)의 `final_test_predictions.parquet` 파일 전수 조사 요청.
- 새롭게 모델링 된 `group_3_2` (stage 3, 3.5, 4) 결과물이 제대로 분리되었는지(그룹1과 안 겹치는지) 확인.
- `group_3_2` 관련 산출물을 Github에 푸시해달라고 요청.

## 2. AI가 한 일 (변경 파일 목록)
- 파이썬 스크립트를 사용하여 `local_dataset.parquet`과 `split_ids.csv`를 통해 Test Set의 올바른 고유 SAMPID 인원 수 확인 (경영 154명, 연구 126명, 교육 129명 등).
- 각 그룹의 `final_test_predictions.parquet` 파일 간 `SAMPID` 교집합 검사 실행.
- `sandbox` 폴더 안의 각 담당자별 `04_model_comparison.ipynb` 코드를 분석하여 직군 필터링(`_subset_bundle`)에 복사-붙여넣기 실수(예: 그룹3이 '경영·사무·금융'으로 필터링 됨)가 있었음을 규명.
- 그룹 1과 그룹 3의 결과가 완벽히 겹친 원인을 사용자에게 보고하고 다른 노트북들의 오류 현황도 파악.
- 새로 실행된 `stage_4_local_group3_2` 파일이 정상적인 인원 수(129명)로 그룹 1과 분리되었음을 확인 (8명의 자연스러운 교집합만 존재).
- `data/result/baseline_42features/modeling/` 하위의 `group3_2` 산출물들을 git add 하고 `feat/didwo-add-group3-2-models` 브랜치에 커밋.

## 3. 내가 검증한 방법과 결과
- AI를 통해 파이썬 스크립트(`value_counts`, `nunique`, `set.intersection`)로 parquet 파일과 csv 파일들을 교차 검증함.
- `group_3_2` 산출물이 그룹 1 결과(154명)와 완전히 분리되어 129명으로 제대로 잡힌 것을 확인함.

## 4. 남은 것·막힌 것
- 현재 그룹 3만 `group_3_2`로 새로 돌려서 푸시했지만, 그룹 2 (연구·공학·산업기술) 등 다른 그룹들도 필터링 문자열이 꼬여서 잘못 돌아갔을 가능성이 있음. 각 조원들이 본인 직군 노트북의 필터링 조건을 점검하고 다시 돌릴 필요가 있음.
