## 2026-08-20 — Global Stage 1 42개 Feature 모델링 구현

### 지침 (내가 시킨 것)

- `baseline_42features`의 Global Train만 사용해 Logistic Regression과 XGBoost를 비교하고, 고정 Test Dataset은 열거나 사용하지 말라고 했다.
- `StratifiedGroupKFold` 5-fold, group=`SAMPID`, random_state=42, F1 scoring, threshold=0.5, CV Train-fold-only 전처리, 설정 파일의 탐색 범위, XGBoost fold별 negative/positive `scale_pos_weight`를 그대로 사용하라고 했다.
- `n_prior_periods`, `sample_weight`, SMOTE·over/undersampling을 사용하지 말고, best parameter·CV·OOF 지표·OOF 예측·지정 시각화를 담은 `notebooks/global/01_first_model.ipynb`를 만들라고 했다. 모델 선택·Feature 제거·결과 해석은 하지 말라고 했다.

### AI가 한 일

- Train 전용 저장 Dataset 로더, 확률 기반 공통 지표 계산, 고정 파라미터 OOF 생성, Stage 1 모델 실행·OOF 저장 함수를 `code/`에 추가했다.
- Notebook은 공용 함수를 호출해 두 모델의 GridSearchCV·OOF를 실행하고 비교표, CV/Fold/OOF 지표, 두 혼동행렬, ROC·Precision-Recall 곡선을 표시하도록 만들었다.

### 검증 / 남은 것

- 실제 baseline Global Train 11,925행·42개 Feature에서 축소 탐색으로 LR·XGBoost의 `run_first_stage_modeling()`을 실행했다. 두 모델 모두 5개 fold F1과 11,925행 OOF 예측을 생성했다. Test Dataset은 호출하지 않았다.
- Notebook의 JSON·모든 Python 셀 컴파일과 `code` 모듈 컴파일을 확인했다. Jupyter의 병렬 process worker는 저장소 패키지명 `code`를 표준 라이브러리 대신 불러 `pdb` import가 실패하는 문제가 있어, Notebook의 GridSearchCV는 같은 탐색·CV 조건을 유지한 채 `n_jobs=1`로 실행하게 했다.
- 실행 중 보고된 `ImportError: cannot import name 'generate_oof_predictions' from partially initialized module 'code.evaluation.oof'`는 `code.model.__init__`이 `first_stage`를 eager import하면서 `oof → code.model → first_stage → oof` 순환이 생긴 문제였다. Stage 1 export를 lazy import로 바꾼 뒤 동일한 `code.evaluation.oof`·`code.model.first_stage` import 순서를 재현해 정상 통과했다.
- 실행 중 보고된 `RocCurveDisplay.from_predictions() got an unexpected keyword argument 'color'`는 설치된 scikit-learn 버전의 display 생성 함수가 `color` keyword를 지원하지 않아 발생했다. Notebook은 display를 먼저 만든 뒤 반환된 `line_` 객체에 색상을 지정하도록 수정했다. Precision-Recall 곡선도 같은 호환 방식을 적용했다.
- 모델 선택과 Stage 2 진행 판단은 실행자가 직접 기록해야 한다.

### 지침 (내가 시킨 것)

- LR/XGBoost 각각의 validation-fold F1 Permutation Importance, LR coefficient, XGBoost gain/weight, 수치형 Pearson/Spearman 상관관계, 적절한 수치형 변수 범위의 VIF, 42개 원 Feature 종합표와 지정 시각화를 요청했다.
- Feature 자동 삭제·제거 추천·최종 목록 생성은 하지 않고, 최종 Feature 선택은 사람이 직접 한다고 했다.

### AI가 한 일

- `code/evaluation/feature_analysis.py`에 Stage 1 고정 파라미터로 SAMPID 5-fold를 다시 학습해 validation fold 원 Feature F1 Permutation Importance를 계산하는 함수를 만들었다. importance mean/std, fold별 값, rank, positive fold count를 반환한다.
- 전처리 후 dummy 열의 LR coefficient와 XGBoost gain/weight를 `features.yaml`의 원 Feature 단위로 묶었다. coefficient/gain은 보조 자료로만 제공하며 자동 선택에 쓰지 않는다.
- 수치형 원 Feature의 Pearson/Spearman 행렬·높은 상관 pair 표와, One-Hot 범주형 및 이진/저변동 변수를 제외한 다값 수치형 VIF를 구현했다.
- `01_first_model.ipynb`가 OOF뿐 아니라 Stage 2 재사용용 `first_stage_summary.csv`, `best_params.json`도 저장하도록 보완했고, Stage 2 Notebook은 이를 읽어 GridSearch 재실행 없이 분석한다.

### 검증 (내가 직접 확인한 것)

- 실제 Global Train의 앞 400 SAMPID(886 Person-Period)만 사용해 LR·XGBoost의 5-fold, 각 Feature 2회 permutation 축소 실행을 통과했다. 두 모델 모두 42개 원 Feature 결과, 5개 fold importance, LR coefficient 요약, XGB gain/weight, 상관·VIF·종합표를 생성했다. Test Dataset은 호출하지 않았다.
