## 지침 (내가 시킨 것)

- 최신 main 기준으로 Global Model 모델링 준비를 요청했다. 지정 문서·설정 파일을 먼저 읽고, 공식 비교 대상을 Logistic Regression과 XGBoost 두 모델로만 반영하되 Decision Tree·Random Forest·LightGBM 구현은 삭제하지 말라고 했다.
- 재사용 기능은 `code/`에, Notebook은 공용 함수를 import해 실행·표·그래프를 확인하는 용도로 만들라고 했다. 모델 선택·결과 해석은 하지 말라고 했다.
- LR/XGBoost 및 공통 구현 상태를 점검하고, XGBoost는 각 CV Train fold의 negative/positive 비율로 `scale_pos_weight`를 계산하게 구현하라고 했다. OOF, Permutation Importance, SAMPID bootstrap 1,000회 95% CI도 점검 대상으로 제시했다.
- `notebooks/global/00_modeling_check.ipynb`에서 실제 Global Dataset과 split의 표본·SAMPID·target·baseline_year·42개 Feature·결측률을 점검하고 세 종류 그래프를 만들라고 했다.

## 검증 (내가 직접 확인한 것)

- `main`이 최신 상태임을 `git pull --ff-only`로 확인했다.
- 실제 baseline Global Dataset은 14,906 Person-Period, split은 7,143 SAMPID(train 5,737 / test 1,406)임을 파일에서 읽어 확인했다.
- 기존 `tune_model()`은 XGBoost `train_negative_positive_ratio` 후보를 발견하면 `NotImplementedError`로 실행을 막고 있음을 확인했다.
- 실제 baseline Dataset에서 Train 11,925행 / 5,737 SAMPID, Test 2,981행 / 1,406 SAMPID, overlap 0, 42개 Feature 누락 0을 확인했다.
- synthetic 데이터로 LR GridSearchCV(F1·StratifiedGroupKFold)와 XGBoost GridSearchCV를 실행했다. XGBoost marker는 3:1 Train 입력에서 3.0, 1:1 Train 입력에서 1.0으로 계산됐다. OOF 80행과 SAMPID bootstrap 25회도 생성했다.
- `jupyter nbconvert`로 Stage 0 Notebook을 실제 Dataset에서 실행해 표와 세 그래프 생성까지 확인했다. Jupyter가 저장소 루트에서 표준 라이브러리 `code`와 충돌하는 환경은 `KHUDA_PROJECT_ROOT`와 Notebook의 import 처리로 우회했다.
