### 판단 근거 (지시 11)

원문을 뒤져 확인한 사실 두 가지로 결정했다.

- 김고운 외(2023)에 **조규판 언급 0회**, '취업불안'은 3회뿐이고 그것도 **다른 척도의 하위요인 이름**으로 등장 → **이 척도는 '취업 스트레스' 척도지 '취업불안' 척도가 아니다.**
- 그러나 같은 논문 **443쪽**에 다리가 있다: *"취업 스트레스는 넓은 관점에서 보면 스트레스의 일종이기 때문에…"* + 저자들이 소개하는 기존 척도에 이미 '취업불안 스트레스'(김혜정·강유리, 2008), '미취업에 대한 불안'(정의석·노안영, 2001)이 하위요인으로 들어 있음 + **채택 척도 문항에 "갑자기 불안해진다"가 3개** 직접 포함.

**결론: 종속변수 = 취업 스트레스.** 구성개념은 측정 도구가 정의하므로 취업 스트레스 척도로 재고 '취업불안이 줄었다'고 쓸 수 없다. 배경·원인 절은 불안 문헌을 쓰되 위 443쪽으로 연결한다. → 07 §0-3

## ⑬ 추가 지시 — 풀 받으면 업데이트 내용 자동 안내

20. "깃허브 업데이트 받으면 팀원들이 **업데이트된 내용이 무엇인지 알 수 있게** 하고 싶어. 각자 자기 작업 결과물을 요약해두면, **다른 사람이 풀 받았을 때 자동으로 안내되도록** 설계하고 싶어."

### 설계

`git`의 **post-merge 훅**이 `git pull` 직후에 실행된다는 점을 이용했다.

1. 올린 사람 → 루트 `업데이트.md` 맨 위에 항목 추가 (AI가 `wrap` 절차에서 자동 작성)
2. 받는 사람 → `git pull` 하면 훅이 `ORIG_HEAD..HEAD` 구간에서 **`업데이트.md`에 추가된 줄만** 뽑아 출력
3. 요약이 없는 커밋이면 → 커밋 목록을 대신 보여주고 "올린 사람에게 요약을 부탁하라"고 안내

**테스트**: 직전 커밋을 ORIG_HEAD로 두고 훅 실행 → 요약 없는 경우의 대체 출력(커밋 목록 + 안내)이 정상 동작함을 확인.

**주의**: post-merge도 `core.hooksPath` 설정이 있어야 돈다. §2-6의 AI 자동 설정 규칙으로 커버되지만, AI 없이 clone만 한 사람은 안내를 못 받는다.
