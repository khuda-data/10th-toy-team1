4. (지금) 두 분석을 합쳐 `작업기록/jungjinmo`에 별도 파일로 커밋·푸쉬.

## AI가 한 일

- 로컬에 재생성된 `data/result/datasets/person_period.parquet`(14,906행/고유 7,143명)을 `SAMPID`로 `groupby`+`pivot`해 `baseline_year` 조합별 인원과 각 조합의 `employment_transition`(outcome) 분포를 전수 계산했다.
- `Toy_project/데이터셋/YP 1~4차 통합 데이터(엑셀).zip`을 직접 재추출해 4개 wave 원자료에서 `student`×`student_type`, `a408/a308/a123`, `c601`×`c635` 값을 크로스탭·집계했다.
- `YP 1-4차 조사 코드북.xlsx`의 "공통, A(학교생활)" 시트에서 `a408`/`a308`/`a123`의 코드북 원문 라벨과 응답 인원을 직접 조회해 사용자 설명과 대조했다.
- `code/pipeline/source_adapter.py`의 `university_type_current`/`university_type_graduate` 파생 로직을 원자료(raw `a408`/`a123`/`a308`)와 값 단위로 대조해, 실제로 어떤 원문항이 어느 파생변수에 반영돼 있는지 확인했다.

## 검증 1 — 과대표집 구조 재분석 (baseline_year 조합별 분해)

**해석은 사람(jungjinmo)이 직접 했고, AI는 원자료 재계산으로 수치·논리만 검증했다.**

**조합별 분해 (Global, 고유 SAMPID 기준)**

| baseline_year 조합 | 인원 | 인원 비중 | 기여 행 수 | 행 비중 |
|---|---:|---:|---:|---:|
| 2021만 | 1,531 | | 1,531 | |
| 2022만 | 338 | | 338 | |
| 2023만 | 458 | | 458 | |
| 2021+2022만 | 1,294 | | 2,588 | |
| 2022+2023만 | 337 | | 674 | |
| 2021+2023만 | 238 | | 476 | |
| 2021+2022+2023 모두 | 2,947 | **41.3%** | 8,841 | **59.3%** |
| **합계** | **7,143** | 100% | **14,906** | 100% |

- 1개 시기만 등장(2,327명, 32.6%) → 2,327행(15.6%)
- 2개 시기 등장(1,869명, 26.2%) → 3,738행(25.1%)
- **3개 시기 모두 등장(2,947명, 41.3%) → 8,841행(59.3%)** — 전체 인원의 41.3%가 전체 학습 행의 59.3%를 차지.

**핵심 발견 — 4,816명(2개 이상 등장) 중 87%(1,631명)는 통계적 상관관계가 아니라 파이프라인 설계가 만드는 결정론적 반복**

- (2021,2022)만 있는 1,294명 — 2021년 행의 outcome이 **100% 전부 0**(미취업 유지)
- (2022,2023)만 있는 337명 — 2022년 행의 outcome이 **100% 전부 0**
- 3개 시기 모두 있는 2,947명 — 2021·2022년 행의 outcome이 **둘 다 100% 전부 0**, 2023년 행만 자유(성공 766 / 실패 2,181)

이유: `build_person_period.py`가 baseline_year마다 독립적으로 "그 해 미취업(`ecoact∈{2,3}`)인가"를 판정해 `pd.concat`하는 구조라, 예를 들어 2022년 baseline 행이 존재하려면 그 사람이 2022년에도 미취업이어야 하고, 그건 곧 "2021→2022 전환은 실패(라벨 0)"라는 뜻이 논리적으로 확정된다.

**행 단위로 보면 문제가 더 커진다**: 3개 시기 모두 등장하는 2,947명이 만드는 label=0 행은 5,894개(2,947×2, 무조건 0)이고, 여기에 (2021,2022)만/​(2022,2023)만 그룹의 강제 0-행(1,294+337=1,631개)까지 더하면 **구조적으로 100% 확정된 label=0 행이 총 7,525개**다. 전체 데이터셋 label=0 행이 11,010개이므로, **전체 0-라벨 행의 68.3%(7,525/11,010)가 "실제로 관측해서 나온 0"이 아니라 "person-period 구조상 자동으로 정해지는 0"**이다. 전체 14,906행 기준으로는 행의 50.5%가 이런 구조적 확정 행이다.

**진짜 상관관계가 있는 부분: 인접하지 않은 (2021,2023)만 있는 238명**

- 이 238명은 2022년 행이 없다 → 2022년에는 이미 취업 상태였다는 뜻 → 2021년 행의 outcome이 **100% 전부 1**(전환 성공)로 확인됨.
- 즉 "2021→22 취업 성공 → 2023년 시점엔 다시 미취업으로 돌아간" 사람들.
- 2023→24 결과: **108명(45.4%) 재취업 성공**, **130명(54.6%) 재실패** — 100%로 결정되지 않고 자연스럽게 갈리는, 취업→재실직 이력을 담은 **진짜 신규 정보**.

**검증 결과**: 위 수치·논리를 `person_period.parquet` 재계산으로 전부 소수점까지 정확히 일치함을 확인했다(반올림 오차 없음).

**왜 문제가 되는지**

1. **손실함수·계수 추정 왜곡**: 행 단위로 loss를 계산하는 모델은 이 41.3%의 사람들에게 사실상 2~3배 가중치를 준다.
2. **통계적 유의성 과대평가**: 행 단위 독립 가정으로 표준오차·신뢰구간을 계산하면 effective sample size가 14,906이 아니라 7,143에 더 가까워 과소평가된다 — `StratifiedGroupKFold(group=SAMPID)`로 Train/Test 누수는 막았지만, **Train 세트 내부의 가중치 불균형은 안 막힘.**
3. **평가지표(F1·AUC) 왜곡**: 반복 등장하는 특정 하위집단(장기 미취업 성향)을 얼마나 잘 맞추는가에 지표가 치우칠 수 있다.

## 검증 2 — 결측치 3개 Feature 코드북 재대조

**해석은 사람(jungjinmo)이 직접 했고, AI는 원자료 zip·코드북 원문 대조로 수치·라벨을 검증했다.**

**① `student_type` (Local 기준 46.0% 결측) — 100% 문항 비해당**

원자료 4개 wave 전부에서 `student`(재학여부) × `student_type` 결측을 크로스탭:

| wave | student=1(재학) 결측률 | student=2(비재학) 결측률 |
|---|---:|---:|
| 1 | 0.0% (0/6,022) | 100.0% (6,191/6,191) |
| 2 | 0.0% (0/4,567) | 100.0% (6,154/6,154) |
| 3 | 0.0% (0/3,362) | 100.0% (6,746/6,746) |
| 4 | 0.0% (0/2,368) | 100.0% (7,297/7,297) |

4개 wave 전부 완벽한 0%/100% 분리 확인. **재학생에게만 의미 있는 파생변수이므로 실제 결측이 아니라 구조적 비해당** — 0으로 채우지 말고 "비재학" 카테고리로 명시 인코딩해야 한다.

**② `university_type` (Local 기준 38.7% 결측) — 비해당 + 이력 누적 미비, 단 원인 변수는 정정 필요**

코드북(`YP 1-4차 조사 코드북.xlsx` "공통, A(학교생활)" 시트) 원문에서 확인한 라벨·응답 인원:

| 변수 | 코드북 라벨 원문 | 2·3·4차 응답 인원 |
|---|---|---|
| `a408` | [동일] 세부학교 유형_대 | 4,205 / 3,088 / 2,086 |
| `a308` | [입\|대] 세부학교 유형_대 | 197 / 114 / 92 |
| `a123` | [졸\|대] 세부학교 유형_대 | 911 / 1,076 / 1,034 |

라벨(동일=유지, 입=입학, 졸=졸업)과 인원수 전부 일치 확인.

**추가 발견 — carry-forward 대상 정정**: `code/pipeline/source_adapter.py`의 `university_type = current.combine_first(graduate)`에서 원자료를 직접 대조한 결과, **`university_type_current`는 이미 `a408`뿐 아니라 `a308`(신규입학)까지 합쳐서 만들어진 파생변수**였다(non-null 3,195명 = a408 3,088명 + a308 non-null 행의 94%(107/114)가 겹침). 즉 **"입학(a308)" 케이스는 이미 파이프라인에 반영돼 있다.**

반면 `university_type_graduate`(a123 기반, non-null 983명)는 그 조사 차수에서만 잡히는 스냅샷이고 다음 차수로 이월되지 않는다. **carry-forward 로직이 필요한 대상은 `university_type_graduate`(a123) 하나로 한정된다** — a308(입학)은 이미 처리돼 있어 손댈 필요 없음.

**③ `recent_employment_prep`(c635, Local 기준 34.6% 결측) — 설문 분기로 인한 비해당**

`c601`(구직활동 여부, 미취업자 전체가 도달) 대비 `c635`(지난 1개월 취업준비 여부) 응답 커버리지:

| wave | c601 응답 | c635 응답 | 커버리지 |
|---|---:|---:|---:|
| 1 | 6,852 | 6,427 | 93.8% |
| 2 | 5,441 | 2,824 | 51.9% |
| 3 | 4,391 | 2,204 | 50.2% |
| 4 | 3,531 | 1,834 | 51.9% |

전부 소수점까지 정확히 일치. 1차와 2~4차 사이의 큰 격차(93.8%→~51%)도 재현됨 — Part Cb→Cc 설문 분기(비경활·비취업준비자는 Cc를 건너뜀)로 인한 비해당이라는 해석이 데이터로 뒷받침된다.

**종합**

| Feature | 결측 성격 | 처리 방향 |
|---|---|---|
| `student_type` | 100% 구조적 비해당 | "비재학" 카테고리로 명시 인코딩 |
| `university_type` | 비해당 + 이력 누적 미비 | 비해당은 카테고리 처리, **`university_type_graduate`(a123)만** 이전 차수 값 이월(carry-forward) 구현 필요 (a308/`university_type_current`는 이미 처리됨) |
| `recent_employment_prep` | 설문 분기(비경활·비취업준비자 스킵)로 인한 비해당 위주 | "비해당(취업준비 흐름 미도달)" 카테고리로 인코딩, 단순 0/1 결측 처리 금지 |

셋 다 `code/config/yp2021_missing_rules.json`의 "진짜 결측 vs 문항 비해당" 구분에서 비해당 쪽 — 0으로 채우면 안 된다는 원칙이 그대로 적용된다.
