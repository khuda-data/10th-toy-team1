## AI가 한 일

1. **코드북·매핑표 대조**로 실제 원자료 문항 확인 (`[YP2021]…코드북_0227.xlsx`, `…매핑표_0227.xlsx`):
   - `e301`(자격증 취득여부)·`e302`(개수)·`e307_1`(1번째 자격증 전공관련도) — **1차(2021) 문항 없음**, 2~4차만 있음.
   - `e101`(직업교육훈련 경험여부)·`e102`(횟수)·`e108_1`(1번째 훈련 총시간) — **1차 없음**, 2~4차만.
   - `d001`/`d002`(경험일자리 유무·횟수, 2~4차)와 `d501`/`d502`(같은 내용의 1차 전용 회고조사 문항) — 짝을 이루는 문항이라 wave별로 다른 컬럼을 씀.
   - `c720`(취업준비 스펙_업무·직무 자격증)은 **1~4차 전부**에 있어서, 자격증 계열 중 유일하게 1차도 커버 가능. `a207`(졸업자 버전, 2~4차)과 OR 결합.
2. `code/pipeline/source_adapter.py` 수정:
   - `_source_columns()`에 위 원자료 컬럼 추가.
   - `_conditional_zero()` 헬퍼 신설 — "여부"가 2(없다)면 하위 개수·시간을 논리적 0으로, 1(있다)이면 실제값, 여부 자체가 결측이면 NA로 채움 (protocol의 "비해당은 논리적 0인 경우만 0" 규칙 적용).
   - `standardize_annual_frames()`에 9개 feature 매핑 추가: `has_certificate`, `certificate_count`, `has_major_related_certificate`, `has_employment_certificate`, `has_vocational_training`, `vocational_training_count`, `vocational_training_hours`, `ever_worked_before`, `past_job_count`.
3. `code/config/yp2021_missing_rules.json`에 위 9개 feature용 특수결측 규칙(9090908/9090909→Missing, blank→NotApplicable) 변수별로 등록.
4. `python -m compileall -q code`로 문법 검사 통과 확인.
5. `python -m code.pipeline.run_pipeline --raw-zip <choi-1110 로컬 원자료 zip>`을 두 번 실행(수정 전/후)해 실제 데이터로 검증.

## 판단이 필요한 지점 〔AI 제안 · 사람 검토 필요〕

- **`has_major_related_certificate`의 "관련 있음" 기준**: `e307_1`(전공 관련도 1~4점, 1=전혀없음~4=매우깊음)에서 **3점 이상**을 "관련 있음(1)"으로 매핑함. 이 임계값(3점)은 AI가 합리적으로 골랐을 뿐 팀이 확정한 기준이 아님 — 다르게 볼 여지 있음(예: 4점만 인정).

## 2차: 나머지 22개 feature 전부 구현 (2026-08-14, 이어서)

### 지침
- "규칙에 맞춰서(Feature 목록 임의 축소 금지 원칙 지키면서) 나머지 피처도 다 코드 짜줘"라는 요청.

### AI가 한 일 — 코드북·매핑표 재대조
- **`major_group`** ← `a413`([공통] 전공계열, 1~4차 **전부** 있음). 값 1~8+97.
- **`months_since_graduation`** ← 기존에 이미 로딩만 되고 안 쓰이던 `eduy`/`edum`(최종학력 취득시점)과 `date{wave}_y/_m`(조사시점)의 개월 차. 새 원자료 컬럼 추가 없이 계산.
- **`prep_effort_01~12`, `prep_effort_other`** ← 2~4차는 `c701a/b/c`(1~3순위, 값1~12+97)를 멀티핫 전개. **1차는 순위형 문항이 없고 `c702~c713` 12개 개별 예/아니오 문항으로 물어보는데, 값 순서가 c701의 1~12 코드와 정확히 같아서(코드북 대조 완료) 1차도 채울 수 있었음** — hanliyagi가 "1차와 2~3차 취업노력 문항의 동등성" 문제로 남겨뒀던 것 해결.
- **`graduation_prep_experience`**(`a193`)·**`graduation_job_search_experience`**(`a194`) — 이미 로딩만 돼있던 컬럼 사용. 1차엔 문항 없음(코드북 확인).
- **`exam_prep_experience`**(`e001`)·**`exam_prep_count`**(`e002`)·**`currently_preparing_exam`**(`e008_1`) — 1차엔 문항 없음(코드북 확인).

### 판단이 필요한 지점 〔AI 제안 · 사람 검토 필요〕
- **`school_work_experience`**: `a186_1`/`a616_1`(재학중 일경험 유형)의 상위 "여부" 게이팅 문항을 코드북에서 못 찾음. "있음(1)"만 판정하고 나머지는 0이 아니라 NA로 둠 — "경험 없음"과 "문항 비해당"을 구분 못 해서 값이 대부분(89~97%) 결측임.
- **`past_work_months`**: 총 근무개월 변수가 원자료에 없어서, 경험일자리 **[1]번째 것의 시작~종료 시점(년/월) 차이만** 계산함. 여러 일자리 총합이 아님(합산 방식은 겹치는 기간 처리 등 추가 설계 필요해 보류). 값이 있는 행이 111개뿐(전체의 3.4%)로 매우 희소함.

### 검증
- `python -m compileall -q code` 통과.
- `python -m code.pipeline.run_pipeline --raw-zip <원자료 zip>` (구조 확인 모드, `--run-modeling` 없이) 재실행 → **`global_dataset.parquet`의 45개 컬럼 중 100% 결측인 컬럼이 0개**로 확인됨(이전엔 27개). 즉 이번 배치로 남은 미구현 feature가 전부 최소한의 실측값을 가짐.
- baseline_year별 결측률을 새 feature마다 개별 확인 — 1차 문항이 원래 없는 것(exam_prep_*, graduation_*)은 2021행 100% 결측으로 "정상", 1차도 커버되는 것(major_group, months_since_graduation, prep_effort_01~12)은 2021행도 실측값이 섞여 있음을 확인.
- 값 분포·기술통계(`months_since_graduation` 평균 44개월, `past_work_months` 평균 8.3개월 등)가 상식적인 범위임을 확인.

### 모델링 시도 중 발견한 별개 이슈 (전처리 스코프 아님, 정보 공유만)
- `--run-modeling`을 시험 삼아 돌려봤더니 `SimpleImputer`가 `TypeError: boolean value of NA is ambiguous`로 실패함.
- 원인: `_yes_no()`(기존 헬퍼, `recent_job_search` 등 기존 feature에도 이미 쓰이던 함수)와 이번에 추가한 `_conditional_zero()`가 pandas nullable 타입(`Int64`/`Float64`)을 반환하는데, `build_features()`가 이걸 그대로 `pd.to_numeric`에 넣어도 nullable dtype이 유지돼서 scikit-learn과 충돌함.
- **기존에 있던 잠재적 버그**임(27개가 다 비어서 여태 아무도 이 단계까지 못 왔던 것) — 사용자가 "전처리까지가 목표"라고 확인해줘서 고치지 않고 정보만 남김. 모델 담당자가 `build_features.py`에서 숫자형은 `.astype("float64")`, 범주형은 `.astype(object)`로 한 번 더 강제 변환하면 해결될 것으로 보임.
