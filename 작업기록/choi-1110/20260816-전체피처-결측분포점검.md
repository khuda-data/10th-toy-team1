## ② AI가 한 일

1. `data/result/datasets/global_dataset.parquet` 기준으로 `features.yaml`의 42개 Feature 전부에 대해 결측률·`NotApplicable` 비율·값 분포(수치형은 min/max/mean/median, 범주형은 값별 건수)를 집계하는 일회성 스크립트를 작성해 실행.
2. 집계 중 `education_level`·`student_status` 두 범주형 Feature에서 같은 코드값이 `"2"`/`"2.0"`처럼 서로 다른 문자열로 쪼개져 있는 것을 발견. 원인 추적 결과 `code/pipeline/source_adapter.py`의 `_categorical_from_reason`이 `pd.to_numeric` 결과(연도별 결측 유무에 따라 int64/float64로 dtype이 들쭉날쭉함)를 그대로 `.astype("string")`한 게 원인이었음.
3. `_categorical_from_reason`을 정수 코드로 캐스팅한 뒤 문자열화하도록 수정(`.astype("Int64").astype("string")`). 이 함수는 `gender`·`region_5`·`education_level`·`student_status`·`student_type`·`university_type`·`major_group` 7개 범주형 Feature가 공통으로 거치는 지점이라 한 번의 수정으로 전부 적용됨. 정의를 고르는 판단이 아니라 타입 캐스팅 버그라 사람 확인 없이 바로 적용.
4. 수정 반영 후 `python -m code.pipeline.run_pipeline --raw-zip C:/Users/pc/Downloads/YP2021_EXCEL_0227.zip`로 전체 파이프라인(Person-Period → Global/Local Dataset)을 백그라운드로 재실행.
5. 재실행 결과로 위 1번 점검을 다시 돌려 수정 전/후를 비교.
6. `plan/details/12-Global-피처엔지니어링-요약.md`에 점검 결과·버그 수정 내역 섹션 추가, `major_group` 결측률 수치 갱신. `회의기록/안건.md`의 `major_group` 항목도 최신 수치(25.16%)로 갱신하고 이전 31.8%가 백필 미반영 스냅샷이었다는 설명 추가.

## ⑤ 후속 — 팀원 모델링 착수 준비 점검 (같은 날 이어서)

사용자가 "13번 설계안 바탕으로 팀원이 모델링 진행하려면 어떻게 해야 하나"라고 물어, 인터페이스 계약(`06-인터페이스.md`)·`code/README.md` 실행 안내를 다시 훑고 실제로 `--run-modeling` 경로를 재현해봤다.

- **직접 재현으로 발견**: `data/result/datasets/global_dataset.parquet`를 그대로 `build_preprocessor().fit_transform()`에 넣으면 `TypeError: boolean value of NA is ambiguous`로 100% 실패함을 확인. 안건함에 이미 "미검증 추정"으로 등록돼 있던 sklearn nullable-dtype 문제(8/15)가, 팀원이 지금 문서 그대로 명령을 치면 바로 만나게 될 실제 차단 이슈임을 확인해 사용자에게 보고.
- **사용자 확정 지시**: AskUserQuestion으로 "제가 지금 고칠지 / 모델 담당자에게 맡길지" 물어 "제가 지금 고침"으로 확정. "커밋 안 된 변경사항 정리"·"README 문구 정리"도 "둘 다 지금 진행"으로 확정.
- **수정**: `code/preprocess/build_features.py`에서 수치형은 `pd.to_numeric(...).astype("float64")`(pandas 결측 마커 `pd.NA`가 `np.nan`으로 자동 변환됨), 범주형은 `.astype("string").astype(object)` 후 `pd.NA`를 `np.nan`으로 명시 치환하도록 고침. 원인은 pandas nullable dtype(`Int64`/`Float64`/`string`)의 결측 마커 `pd.NA`를 scikit-learn의 `SimpleImputer`가 numpy object 배열로 받아 `X != X` 비교에서 못 다루는 것.
- **검증**: 고친 뒤 `build_preprocessor().fit_transform()`이 정상 동작(shape (14906, 69))함을 확인. 실제 CLI 경로(`--run-modeling --model logistic_regression`) 전체를 백그라운드로 재실행해 `metrics.csv`·`feature_importance.csv`까지 끝까지 도는지 별도로 검증 중(결과는 이어서 기록).
- `code/README.md`의 "완성되기 전에는 모델 실행을 의도적으로 막는다"는 8/14 시점 문구가 42개 Feature 구현 완료(8/16) 이후 stale해진 것을 확인해 갱신. `회의기록/안건.md`의 sklearn 버그 항목도 해결 처리.
