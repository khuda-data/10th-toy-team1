## ② AI가 한 일

1. `code/pipeline/build_person_period.py`에 Group A/D 헬퍼 함수 3개 추가: `_prior_year_column`(연도별 조회 공통 함수), `_backfill_group_a`, `_accumulate_group_d`. 메인 루프에서 `period` 생성 직후 호출하도록 연결.
2. 판단 근거 확보를 위해 사용자가 지정한 직업력 코드북(`직업력코드북` 시트)을 직접 열어 확인 — `JOBWAVE`/`JOBSEQ` 기반의 별도 일자리 로스터 구조를 설명하지만, **그 로스터의 실제 데이터 파일은 프로젝트 폴더에 없고 코드북만 있음**을 확인. `past_job_count`·`past_work_months`를 이 방식으로 정확히 재구성하는 건 이번엔 불가능하다고 판단.
3. 일반 코드북(`E(시험준비등), F(가구배경)`·`D(경험일자리)` 시트)에서 `e301`(자격증)·`e101`(직업훈련)·`e001`(시험준비)·`d001/d002`(경험일자리)의 연도별 "있다" 응답자 수를 확인 — 전체 응답자 감소폭(약 10%)보다 훨씬 크게 줄어드는 공통 패턴을 발견(예: e301 2차 1,215명→3차 347명→4차 283명). 각 연도 값이 "그 해 새로 생긴 건수"일 가능성이 높다고 판단해 근거로 제시.
4. 사용자 확정을 거쳐 개수형 6개 중 4개(`certificate_count`·`vocational_training_count`·`exam_prep_count`·`past_job_count`)는 baseline까지 연도별 합산, 기간형 2개(`vocational_training_hours`·`past_work_months`, 이미 "1번째 episode만 계산" 한계가 안건함에 등록됨)는 이번엔 손대지 않기로 확정.
5. `plan/details/06-인터페이스.md`에 person_period.parquet 계약 갱신 사항 한 단락 추가.
