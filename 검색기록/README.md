# 검색기록 — 모든 검색의 과정과 판정

**무엇**: 검색 세션 1번 = 파일 1개 (`YYYYMMDD-<git아이디>-<주제>.md`). **논문, 데이터셋, 라이브러리, API, 기술 해결책 — 무엇을 찾든** 어디서 어떤 검색어로 찾았고, 나온 후보를 왜 채택/보류/제외했는지를 남긴다.

**왜 만들었나**: 검색 기록이 없으면 ① 팀원들이 같은 검색을 반복하고 ② "그건 왜 안 썼더라"를 아무도 답 못 하고 ③ 채택한 것의 근거가 사라진다. 검색은 한 번, 기록은 영구. (UXC 연구실 `신규논문검색리스트` 규율의 확장판)

**규칙**:
- **검색 전에 이 폴더를 먼저 확인** — 같은 주제의 기존 기록이 있으면 이어서 (중복 검색 방지).
- 검색어는 **입력한 그대로** 기록 (같은 검색을 재현할 수 있게).
- 후보마다 판정(채택·보류·제외)과 **이유 한 줄** 필수.
- 직접 쓸 필요 없다 — **AI가 검색하면서 자동으로 작성한다** (AGENTS.md §12).

**유형별 후속 연계**:

| 검색 유형 | 채택 시 이어지는 것 |
|---|---|
| 논문 | `plan/details/03-논문인덱스.md` 중복 확인 → PDF 확보 → `논문/<코드명>/` 컨벤션 → (필요시) 해설 제작 |
| 데이터셋 | 다운로드 → `data/raw/` + 출처 기록 표 (`data/README.md`) |
| 라이브러리·API·기술 | 팀이 정할 문제면 `회의기록/안건.md`에, 인터페이스에 영향 있으면 `plan/details/06-인터페이스.md`에 |

## 템플릿 (AI가 자동 작성)

```markdown
# YYYY-MM-DD 검색 — <주제 한 줄>

- 검색한 사람: <git아이디> · 유형: 논문 / 데이터셋 / 라이브러리 / 기술
- 목적: (어떤 결정·작업을 위해 찾는가)
- 사전 확인: 기존 검색기록 O건, (논문이면) 03-논문인덱스 중복 O건

## 검색 내역 (입력한 그대로)
| # | 검색처 | 검색어 | 결과 수 |
|---|---|---|---|

## 후보와 판정
| 이름 (출처·연도) | 링크 | 한줄평 | 판정 + 이유 |
|---|---|---|---|

## 다음 액션
- (채택한 것의 후속 연계 — 위 표 참조)
```
