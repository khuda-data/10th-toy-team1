# 인터페이스 합의 — YP2021 공통 파이프라인 계약

> 이 문서는 `code/` 모듈과 `data/result/` 파일의 **실제 계약**이다. 각 담당자는 내부 구현을 자유롭게 바꿀 수 있지만, 여기 적힌 함수 입력·출력과 파일 스키마는 바꾸지 않는다.
>
> 바꿔야 하면 먼저 이 문서와 `code/config/`을 같은 PR에서 갱신하고, 이유·영향 범위를 팀에 공유한다. 분석 기준 자체 변경은 [`11-YP2021-공통-전처리-모델링-프로토콜.md`](11-YP2021-공통-전처리-모델링-프로토콜.md)의 변경 절차를 따른다.

## 1. 공통 식별·분할 규칙

| 항목 | 계약 |
|---|---|
| 개인 식별자 | `SAMPID` · `string` · 앞자리 0 보존 가능하므로 수치 계산 금지 |
| 분석 행 | 기준연도 미취업자 전체의 `SAMPID × baseline_year` Person-Period |
| 기준연도 | `2021`, `2022`, `2023` · `int16` |
| 결과연도 | `baseline_year + 1` · `int16` |
| Target | `employment_transition` · `int8` · 취업=1, 실업/비경제활동=0 |
| 분할 단위 | `SAMPID` 전체 행. 같은 사람이 Train/Test에 함께 있으면 안 됨 |
| 고정 seed | `42` |
| Global/Local | Global에서 만든 동일 `split_ids.csv`를 사용 |

## 2. 공용 파일 계약

> **실험별 경로 분리(2026-08-18, wjdwlsah 지시)**: 아래 `data/result/...` 경로는 전부
> `data/result/<experiment>/...`로 실험 이름 하위에 독립적으로 저장된다. `<experiment>`는
> `run_pipeline.experiment_name(use_n_prior_periods, use_sample_weight)`이 정하며 네 가지뿐이다:
> `baseline_42features`(둘 다 False, 기본값) · `with_n_prior_periods` · `with_sample_weight` ·
> `with_n_prior_periods_and_sample_weight`. `--compare-oversampling-mitigation`은 raw 데이터를
> 한 번만 읽어 앞의 세 조합(마지막 조합 제외)을 전부 만든다. 세 실험은 `models/`의 `.joblib`
> 파일까지 완전히 분리돼 서로 덮어쓰지 않는다.

### 2.1 `data/result/<experiment>/datasets/person_period.parquet`

만드는 모듈: `pipeline/build_person_period.py`
쓰는 모듈: `pipeline/build_global.py`, `pipeline/build_local.py`, `preprocess/`

| 컬럼 | 타입 | 의미 |
|---|---|---|
| `SAMPID` | string | 패널 개인 ID |
| `baseline_year` | int16 | Feature를 관측한 연도 |
| `target_year` | int16 | Target을 관측한 다음 연도 |
| `ecoact` | Int64 | 기준연도 경제활동상태 원코드(2/3만 존재) |
| `job_seeker` | Int64 | 기준연도 `y**c602` 구직 가능 여부 원코드. 기준연도 상태·Feature 정보 |
| `recent_employment_prep` | Int64 | 기준연도 최근 1개월 취업준비 여부(있음=1). Feature 정보 |
| `recent_employment_prep_reason` | string | `recent_employment_prep`이 NA일 때의 원자료 사유: `Missing` 또는 `NotApplicable` |
| `recent_job_search` | Int64 | 구직 가능 여부 또는 지난 1년 구직활동 중 하나라도 있음=1. 두 원문항이 모두 미관측이면 NA |
| `recent_job_search_reason` | string | `recent_job_search`가 NA일 때의 원자료 사유: `Missing` 또는 `NotApplicable` |
| `nonemployment_type` | string | `unemployed` 또는 `economically_inactive` |
| `employment_transition` | int8 | 다음연도 취업 전환 Target |
| `n_prior_periods` | int64 | 오버샘플링 완화용(2026-08-18). 같은 SAMPID가 이전 baseline_year에 몇 번 더 등장했는지(0부터). Global 전체 이력 기준으로 여기서 한 번만 계산하고, Local로 필터링돼도 값을 그대로 유지한다. **이 컬럼은 여기(person_period)엔 항상 있지만, `features.yaml`의 `optional_features:`에 있어 `build_global_dataset(..., use_n_prior_periods=True)`로 명시했을 때만 X(Feature)에 포함된다** — 기본값은 미포함(42개 Feature 그대로) |
| `features.yaml`의 `features:` 42개 | 설정 타입 | 기준연도까지 알 수 있는 공통 원 Feature. 항상 X에 포함 |

`person_period.parquet`에는 **다음연도 `ECOACT` 외의 다음연도 변수**를 넣지 않는다.

`features.yaml`의 Feature 중 일부는 13번 설계안(`13-YP2021-PersonPeriod-전처리-설계안.md`) §2·§3 그룹별 결측 처리 원칙에 따라 baseline 이전 연도 값으로 이미 보완되어 있다 — Group A(`gender`·`education_level`·`major_group`)는 baseline 실제 결측일 때만 최신순 과거 유효값, Group D 경험여부형 9개는 baseline까지 한 해라도 1이면 1, Group D 개수형 4개(`certificate_count`·`vocational_training_count`·`exam_prep_count`·`past_job_count`)는 baseline까지 연도별 합산이다. 나머지 Feature는 baseline 한 해 값만 쓴다. 구현·근거는 `code/pipeline/build_person_period.py`의 `_backfill_group_a`·`_accumulate_group_d` 참조.

### 2.2 `data/result/<experiment>/datasets/global_dataset.parquet`

만드는 모듈: `pipeline/build_global.py`
쓰는 모듈: `model/`, `evaluation/`

`person_period.parquet`에서 아래 컬럼만 남긴 모델 입력 파일이다.

| 컬럼 묶음 | 타입 | 의미 |
|---|---|---|
| `SAMPID`, `baseline_year`, `target_year` | 위와 같음 | 분할·감사 메타데이터 |
| `features.yaml`의 `features:` 42개(+`use_n_prior_periods=True`면 `n_prior_periods` 포함 43개) | 설정 타입 | Global/Local 공통 입력. `job_group`은 Feature가 아님 |
| `employment_transition` | int8 | Target |
| `sample_weight` | float64 | 오버샘플링 완화용(2026-08-18). `1 / 이 데이터셋 안에서 그 사람의 행 수` — 사람당 가중치 합이 1이 되게 한다. **파일에는 use_sample_weight 값과 무관하게 항상 저장된다** — `run_pipeline._fit_model(..., use_sample_weight=True)`일 때만 실제로 `model/tune.py`·`model/train.py`의 학습(fit)에 반영되고, 기본값(False)에서는 계산만 해두고 학습엔 안 쓴다. `evaluate_model`의 지표 계산에는 항상 반영되지 않는다 |

### 2.3 `data/result/<experiment>/datasets/local_dataset.parquet`

만드는 모듈: `pipeline/build_local.py`
쓰는 모듈: `model/`, `evaluation/`

Global Dataset과 **동일한 Feature·Target**에 다음 메타데이터만 추가한다.

| 컬럼 | 타입 | 의미 |
|---|---|---|
| `hope_job_keco` | string | 기준연도까지 가장 최근 실제 희망직업 KECO 대분류 |
| `hope_job_year` | int16 | 그 응답의 조사연도. `baseline_year` 이하 |
| `hope_job_source` | string | `current_preparation` 또는 `graduation_future` |
| `job_group` | string | `keco_mapping.csv`로 변환한 6개 직군 |

`sample_weight`는 Global 값을 물려받지 않고 **이 Local 부분집합 자체의 행 수 기준으로 다시 계산**한다(같은 사람이 baseline_year마다 다른 직군을 희망했다면 Global 등장 횟수와 달라질 수 있음). 직군별로 다시 쪼갤 때(`run_pipeline.py`의 `_subset_bundle`)도 그 직군 부분집합 기준으로 한 번 더 재계산한다 — `n_prior_periods`(Global 이력을 그대로 유지)와는 반대 원칙이니 혼동하지 말 것.

## 3. Python 함수 계약

| 함수 | 입력 | 출력 | 책임 |
|---|---|---|---|
| `build_person_period_dataset(annual_data)` | 2021~2024 표준 연도별 DataFrame | Person-Period DataFrame | 양 연도 응답, 기준연도 `ECOACT∈{2,3}`, 다음연도 `ECOACT∈{1,2,3}`만 포함해 Target 생성. 구직·취업준비 여부로 제한하지 않음 |
| `build_global_dataset(person_period, feature_config, *, use_n_prior_periods=False)` | Person-Period, `features.yaml` | `DatasetBundle(X, y, groups, metadata, sample_weight)` | 공통 Feature를 순서·타입대로 검증. `sample_weight`는 입력받은 프레임 자체의 SAMPID 행 수 기준(2026-08-18). `use_n_prior_periods=True`일 때만 `n_prior_periods`가 X에 43번째 컬럼으로 들어간다(2026-08-18) |
| `build_local_dataset(person_period, hope_job_history, keco_mapping, feature_config, *, use_n_prior_periods=False)` | Person-Period, 희망직업 이력, KECO 표 | Local `DatasetBundle` | 기준시점 이하 최신 실제 희망직업을 선택·매핑. `sample_weight`는 Local 부분집합 기준으로 재계산. `use_n_prior_periods`는 내부 `build_global_dataset` 호출에 그대로 전달 |
| `build_features(frame, feature_config, *, strict=True, extra_features=None)` | 기준연도 DataFrame | 원 Feature DataFrame | Feature 누락·타입 검증. `extra_features`는 `optional_features:`에 등록된 이름만 받는다(예: `["n_prior_periods"]`) — 기본값(None)은 기존 42개와 완전히 동일(2026-08-18) |
| `build_preprocessor(X_train, feature_config, model_name)` | Train X만 | 미학습 sklearn Pipeline | Train-only 결측·희소범주·One-Hot·스케일링 정의. numeric/categorical 컬럼 목록은 `X_train.columns`에 실제로 있는 것만 써서 optional Feature 포함 여부에 자동으로 맞춘다(2026-08-18) |
| `train_model(X_train, y_train, groups_train, ..., sample_weight_train=None)` | Train X/y/SAMPID(+가중치) | 학습된 sklearn Pipeline | 공통 모델을 fit. `sample_weight_train`은 `model__sample_weight`로 라우팅. `None`이면(기본값) 가중치 없이 학습 |
| `tune_model(X_train, y_train, groups_train, ..., sample_weight_train=None)` | Train X/y/SAMPID(+가중치) | 학습된 `GridSearchCV`/`RandomizedSearchCV` | Group CV와 F1로 파라미터 선택. `sample_weight_train`은 fit에만 반영, 검증 fold 채점에는 미반영 〔AI 제안 · 사람 검토 필요〕 |
| `evaluate_model(model, X_test, y_test)` | 최종 model, Test X/y | metrics dict, prediction DataFrame | threshold=0.5의 고정 지표 계산 |
| `calculate_feature_importance(model, X_test, y_test)` | 최종 model, 원 Feature Test X/y | Importance DataFrame | Test 원 Feature Permutation Importance |
| `run_pipeline.experiment_name(*, use_n_prior_periods, use_sample_weight)` | 두 bool 플래그 | 실험 이름 문자열 | 2.1~2.8 전체의 `<experiment>` 경로·`experiment` 컬럼 값을 결정(2026-08-18) |
| `run_pipeline._fit_model(bundle, ..., use_sample_weight=False)` | DatasetBundle, 학습 옵션 | (fitted, best_params) | `use_sample_weight=True`일 때만 `bundle.sample_weight`를 `train_model`/`tune_model`에 전달. 기본값은 미전달(2026-08-18) |

## 4. 연결 순서·책임 경계

```text
원자료 zip
  → source_adapter (원변수명·특수결측만 표준화)
  → build_person_period_dataset
  → build_global_dataset / build_local_dataset
  → build_split_ids (Global에서 1회)
  → build_preprocessor (Train에서만 fit)
  → train_model 또는 tune_model
  → evaluate_model / calculate_feature_importance
  → metrics.csv / feature_importance.csv / best_params.json
```

- `source_adapter` 담당자는 원변수 매핑과 코드북 분기를 구현한다. 특수결측은 `code/config/yp2021_missing_rules.json`에 코드북 근거와 함께 변수별로 등록하며, 숫자 범위로 일괄 처리하지 않는다. Feature 정의 자체를 변경하지 않는다.
- `preprocess` 담당자는 Global/Local 공통 전처리를 구현한다. Local에만 다른 처리를 넣지 않는다.
- `model` 담당자는 `model_config.yaml` 안에서만 모델과 탐색을 구현한다.
- `evaluation` 담당자는 Test를 모델 선택에 쓰지 않고, 여기의 출력 스키마를 채운다.
