# 협업 통합 절차 — 웹이든 분석이든, 합치기는 첫날 설계다

> 여러 명이 만든 결과물을 문제없이 하나로 합치는 방법. 웹 개발·데이터 분석·모델링 전부 같은 원리로 돌아간다.
> **AI 규칙**: 팀원이 협업 결과물(공용 코드·공용 데이터) 작업을 시작하면 이 절차를 기준으로 안내하라.

## 원리 — 합치기는 git이 한다. 사람은 "나누기"만 잘하면 된다

git의 머지(merge, 변경 합치기)는 **서로 다른 파일**의 변경을 100% 자동으로 합친다. 충돌은 **같은 파일의 같은 부분**을 두 명이 고쳤을 때만 난다.
→ 그래서 "모듈 폴더마다 주인 1명"(AGENTS.md §8)이 곧 합치기 전략이다. 잘 나누면 합치기 버튼만 누르면 된다.

## 4단계

### 1단계. 뼈대 먼저

협업 작업을 시작하면 **돌아가는 최소 버전**을 main의 `code/`에 가장 먼저 만든다 (담당 1명이 세팅).

- 웹이면: 빈 페이지 + "준비 중"이라고만 답하는 API 하나라도 **실행되는** 앱
- 분석이면: raw 읽기 → 전처리 → 결과 저장까지 빈 껍데기로라도 **흐르는** 파이프라인 스크립트

뼈대가 없으면 각자 만든 부품을 꽂을 자리가 없다. 뼈대 없이 각자 완성해 오면 마지막에 용접해야 하고, 그게 통합 지옥이다.

### 2단계. 약속(인터페이스) 먼저 — `06-인터페이스.md`에 기록

모듈/단계 사이에 **주고받는 것의 형식**만 합의해서 문서에 적는다. 약속만 지키면 내부 구현은 각자 자유고, 서로의 코드를 몰라도 된다.

- 웹: API 주소, 요청/응답 JSON 형식
- 분석·모델: 파일 포맷, 컬럼명, 타입, 단위, 좌표계 (예: `links.parquet`, `link_id: str`, `length_m: float`)

**상대 파트가 아직 없으면 가짜(mock) 데이터로 개발한다** — 약속된 형식 그대로 만든 예시 데이터를 놓고 내 파트를 완성한 뒤, 진짜가 오면 바꿔 끼운다.

**약속 변경은 임의로 하지 않는다.** 형식을 바꿔야 하면 `06-인터페이스.md`를 고치는 PR을 올리고 팀 채팅에 알린다. 쓰는 쪽이 모르는 채 형식이 바뀌는 것이 통합 사고의 90%다.

### 3단계. 각자: sandbox 실험 → 자기 모듈 폴더 구현 → 브랜치 → PR

AGENTS.md §8 그대로. 핵심은 하나 — **같은 파일을 두 명이 만지는 상황을 만들지 않는 것.**

### 4단계. 작게 자주 합치고, 합친 것을 실행해본다

- **며칠 단위의 작은 PR로 자주 머지한다.** 2주치를 모았다가 한 방에 합치면 그때는 정말 어렵다.
- 머지되면 팀원들은 `git pull`로 바로 받는다. main과 내 브랜치의 차이를 오래 벌리지 않는다.
- **머지 후 main을 pull 받아 실행해보는 "통합 확인" 담당**을 정한다 (기본: 팀장). main은 항상 실행 가능한 상태를 유지한다.

## 협업 작업 시작 전 체크리스트

- [ ] 뼈대가 main에 있는가? (없으면 이번 작업 = 뼈대 만들기)
- [ ] 내 파트의 입력·출력이 `06-인터페이스.md`에 적혀 있는가? (없으면 먼저 합의해서 적기)
- [ ] 나는 내 폴더만 만지고 있는가?
- [ ] 마지막 머지에서 일주일 이상 지나지 않았는가?

## 부록 — 브랜치, 처음이라면

브랜치(branch)는 "폴더 복사"가 아니라 **같은 폴더 안에서 갈아끼우는 평행 작업 줄기**다. 게임의 세이브 슬롯처럼, main을 건드리지 않고 내 슬롯에 커밋을 쌓다가 다 되면 합친다.

```bash
git switch -c feat/hoyeol-mock-api   # ① 새 브랜치를 만들고 그리로 이동
# ... 작업하고 커밋을 여러 번 쌓는다 (전부 이 브랜치에만 쌓임) ...
git push origin feat/hoyeol-mock-api # ② 원격(GitHub)에 올리기
# ③ GitHub 페이지에 뜨는 "Compare & pull request" 버튼 → PR 생성 → 리뷰 → Merge
git switch main                      # ④ main으로 돌아와서
git pull                             # ⑤ 합쳐진 결과 받기
git branch -d feat/hoyeol-mock-api   # ⑥ 다 쓴 브랜치 삭제 (정리)
```

처음에 헷갈리는 것 세 가지:

1. **브랜치를 바꾸면 폴더 내용물이 실제로 변한다.** 파일이 사라진 게 아니라 다른 슬롯으로 갈아끼운 것. `git switch main` 하면 돌아온다.
2. **내가 지금 어느 브랜치에 있는지** 모르겠으면 `git branch` (현재 위치에 `*` 표시).
3. 커밋 안 한 변경이 있으면 브랜치 이동이 막힐 수 있다 → 먼저 커밋하거나 AI에게 물어보기.

귀찮으면 AI에게 통째로: **"브랜치 만들어서 작업하고, 끝나면 PR 올릴 준비까지 해줘"** — 위 절차를 AI가 대신 해준다.
