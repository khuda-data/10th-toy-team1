> 이 문서는 YP2021 직군별 취업전환 예측 프로젝트에서 팀 전체가 동일하게 따라야 하는 **공통 전처리·데이터 분할·모델링·평가 기준의 정본**이다.
>
> 실제 파일·컬럼·함수 계약은 `plan/details/06-인터페이스.md`, 공통 설정값은 `code/config/`을 따른다. 개인 실험은 가능하지만, 이 문서의 연구 기준을 팀원 개인 판단으로 변경해서는 안 된다.

# 0. 연구 질문과 분석 목적

이번 프로젝트에서는 YP2021 1~4차 패널자료를 이용하여 **기준연도에 미취업 상태인 청년이 다음연도에 취업으로 전환하는지**를 예측한다.

두 종류의 모델을 만든다.

- **Global Model**: 희망직군을 구분하지 않고 기준연도 미취업 청년 전체를 학습한다.
- **Local Model**: Global 분석대상 중 baseline year까지 유효한 희망직업 정보가 있는 사람을 6개 희망직군으로 나누어 직군별로 별도 학습한다.

최종적으로 다음 두 질문에 답한다.

1. **희망직군별 Local Model이 전체 미취업 청년을 학습한 Global Model보다 해당 직군의 취업전환을 더 잘 예측하는가?**
2. **희망직군에 따라 취업전환 예측에서 중요하게 사용되는 Feature가 다르게 나타나는가?**

이번 분석은 예측모델 비교를 목적으로 한다. Feature Importance가 높다는 사실을 해당 요소가 취업을 **원인적으로 증가시킨다**는 의미로 해석하지 않는다.

---

# 1. 분석 단위: Person-Period

분석 단위는 `SAMPID × baseline_year`이다.

한 행은 한 사람의 특정 기준연도 상태와 그 다음연도의 취업전환 결과를 연결한다.

| Person-Period | Feature 기준시점 | Target 시점 |
|---|---:|---:|
| 2021 → 2022 | 2021 | 2022 |
| 2022 → 2023 | 2022 | 2023 |
| 2023 → 2024 | 2023 | 2024 |

같은 사람이 여러 차수에 응답했다면 서로 다른 `baseline_year`의 여러 행으로 포함될 수 있다. 따라서 Train/Test 분할에서는 같은 `SAMPID`가 양쪽에 동시에 들어가지 않도록 반드시 그룹 단위 분할을 사용한다.

---

# 2. 분석대상

각 Person-Period에서 다음 조건을 모두 만족하는 사람만 포함한다.

1. 기준연도 조사 응답이 유효함
2. 다음연도 조사 응답이 유효함
3. 기준연도 `ECOACT ∈ {2, 3}`
   - 2: 실업
   - 3: 비경제활동
4. 다음연도 `ECOACT ∈ {1, 2, 3}`으로 Target을 판정할 수 있음

즉 **기준연도 미취업자 전체**가 Global 분석대상이다.

다음 항목은 더 이상 분석대상 필터로 사용하지 않는다.

- `y**c602`: 현재 구직 여부
- `y**c635`: 최근 취업준비 여부
- 직업훈련 여부
- 시험준비 여부
- 기타 취업준비 관련 상태

이 변수들은 분석대상을 제한하는 대신 **Feature로 유지**한다. 학생 역시 기준연도에 미취업이고 위 조건을 만족한다면 자동 제외하지 않는다. 학생 여부 자체를 Feature로 사용한다.

# 3. 검증된 Global 표본

공통 코드를 원자료에 적용해 확인한 Global Person-Period 표본은 다음과 같다.

| 전환 | 전체 행 | 취업전환 1 | 미취업 유지 0 | 취업전환율 |
|---|---:|---:|---:|---:|
| 2021 → 2022 | 6,010 | 1,349 | 4,661 | 22.45% |
| 2022 → 2023 | 4,916 | 1,333 | 3,583 | 27.12% |

| **합계** | **14,906** | **3,896** | **11,010** | **26.14%** |

- 고유 `SAMPID`: **7,143명**

이 수치는 이후 Person-Period 생성 로직 검증 기준으로 사용한다.

# 4. Target 정의

Target 변수명은 `employment_transition`으로 통일한다.

```text
다음연도 ECOACT = 1     → employment_transition = 1
다음연도 ECOACT = 2, 3  → employment_transition = 0
```

다음연도 `ECOACT`가 결측 또는 1/2/3 이외의 값이면 0으로 대체하지 않고 해당 Person-Period를 Target 분석대상에서 제외한다.

Local Model에서도 실제로 어느 직군에 취업했는지는 Target에 포함하지 않는다. 희망직군과 실제 취업직군의 일치 여부는 후속 분석 주제로 남긴다.

---

# 5. 시간 기준과 미래정보 누수 방지

모든 Feature는 **각 Person-Period의 baseline year까지 실제로 알 수 있었던 정보만 사용**한다.

- 2021 → 2022 행: 2021년까지의 정보만 사용
- 2022 → 2023 행: 2022년까지의 정보만 사용
- 2023 → 2024 행: 2023년까지의 정보만 사용

다음연도 정보 중 사용할 수 있는 것은 Target 생성을 위한 `ECOACT`뿐이다.

다음연도의 임금, 실제 직종, 근로형태, 구직활동, 취업준비, 자격증, 직업훈련, 시험준비, 일자리 경험 등은 Feature에 포함하지 않는다.

# 6. 공통 Feature 설계

Global과 Local은 **동일한 Feature 목록**을 사용한다. Local 소속을 정하는 `hope_job_keco`, `hope_job_year`, `hope_job_source`, `job_group`은 메타데이터이며 모델의 입력 Feature로 사용하지 않는다.

## 6.1 인구통계

- 성별
- 연령
- 거주지역 5권역
- baseline year

`baseline_year`는 연도별 노동시장 환경 차이를 통제하기 위한 범주형 변수로 사용한다.

## 6.2 교육

- 최종학력
- 학생 여부
- 학생 유형
- 대학 유형
- 전공 대계열
- 졸업 후 경과개월

## 6.3 미취업 상태·구직·취업준비

- 기준연도 미취업 상태 유형: 실업 / 비경제활동
- 최근 구직경험
- 최근 취업준비 경험
- 취업준비 활동 유형
- 졸업 전후 취업준비·구직 경험

**구직·취업준비 여부를 표본 필터로 사용하지 않고 전체 미취업자 안에서 취업전환을 설명하는 Feature로 사용한다.**

## 6.4 자격증

- 자격증 보유 여부
- baseline year까지의 누적 자격증 수
- 취업 목적 자격증 여부
- 전공 관련 자격증 여부

## 6.5 직업훈련

- 직업훈련 경험 여부
- baseline year까지 누적 훈련 횟수
- baseline year까지 누적 훈련시간

## 6.6 시험준비

- 시험준비 경험 여부
- 시험준비 횟수
- 현재 시험준비 여부

## 6.7 일경험

- 재학 중 일경험
- baseline year 이전 근로경험 여부
- 과거 일자리 수
- baseline year까지 누적 근로개월

# 7. 상태형 변수와 이력형 변수

상태형 변수는 해당 baseline year의 값을 사용한다. 예: 연령, 지역, 학생 여부, 최종학력, 미취업 상태 유형, 현재 시험준비 여부.

이력형 변수는 baseline year까지 실제로 관측된 이력만 사용한다. 예: 누적 자격증 수, 누적 직업훈련 횟수·시간, 과거 일자리 수, 누적 근로개월.

같은 과거 경험이 여러 차수에서 반복 보고되는 경우 가능한 범위에서 코드·기간·시점 등을 이용해 중복 제거한다. 다음 차수에서 새롭게 관측된 경험을 과거 baseline 행에 소급하여 넣지 않는다.

# 8. 결측·비해당·설문 분기 처리

YP2021은 설문 분기가 많기 때문에 **실제 결측**, **비해당**, **논리적 0**을 구분한다.

## 8.1 실제 결측

- 수치형: Train fold의 median
- 범주형: `Missing`

Test 또는 Validation의 정보를 사용해 대체값을 계산하지 않는다.

## 8.2 비해당

설문 분기로 인해 응답 대상이 아니었던 경우 0이라는 의미가 성립하지 않으면 `NotApplicable`로 유지한다.

## 8.3 논리적 0

설문 구조상 실제로 해당 경험이 없다는 것이 확실한 경우에만 0으로 처리한다.

## 8.4 특수결측

무응답, 모름, 응답거절 등 특수코드는 **변수별 코드북 기준**으로 처리한다. 하나의 숫자 범위를 모든 변수에 공통 적용하지 않는다.

공통 구현에서는 `code/config/yp2021_missing_rules.json`을 기준으로 변수별 특수결측 규칙을 관리한다.

---

# 9. 범주형 변수 처리

- `OneHotEncoder(handle_unknown="ignore")`
- Train 기준 빈도 10 미만 범주는 `Other`로 통합
- `Missing`은 `Other`와 합치지 않음
- `NotApplicable`도 `Other`와 합치지 않음

의미상 여러 세부 범주를 합쳐야 하는 경우에는 학습 결과를 보고 사후적으로 합치지 않고 사전에 팀이 합의한 의미 기반 그룹을 사용한다.

---

# 10. 수치형 변수와 이상치

일반적인 IQR 또는 z-score 기준으로 관측 행을 일괄 삭제하지 않는다.

- 코드북상 유효하지 않은 코드 → 결측 처리
- 논리적으로 불가능한 값 → 코드북·설문지 확인 후 처리
- 실제 발생 가능한 극단값 → 유지
- 단순히 값이 크거나 작다는 이유만으로 삭제하지 않음

# 15. Train/Test 분할

분할 단위는 `SAMPID`이다.

```python
StratifiedGroupKFold(
    n_splits=5,
    shuffle=True,
    random_state=42
)
```

- `outer_fold = 0`을 고정 Test로 사용
- 나머지 4개 fold를 Train으로 사용
- 약 Train 80% / Test 20%

현재 Global 모집단 기준:

- 전체 고유 SAMPID: **7,143명**
- Train: **5,737명**
- Test: **1,406명**

`split_ids.csv`는 Global Dataset에서 한 번만 생성한다. 모든 Local Dataset은 동일 SAMPID의 Global split 소속을 그대로 따른다.

# 16. Global과 Local의 공정한 비교

각 희망직군에서 **같은 Local Test Sample**에 두 모델을 모두 적용한다.

```text
해당 직군 Local Test Sample
        │
        ├─ Global Model 예측
        └─ 해당 직군 Local Model 예측
```

Local Test에 들어가는 사람은 Global 학습 데이터에 들어가면 안 된다.

핵심 비교값은 `ΔF1 = Local F1 - Global-on-Local F1`이다.

# 17. Local Model 최소 표본 기준

# 19. 하이퍼파라미터 탐색 범위

- `max_iter = 2000`

---

# 20. 교차검증과 튜닝

기본 탐색 방법은 `GridSearchCV`이다.

Train 내부에서 `StratifiedGroupKFold`, group=`SAMPID`, scoring=`F1`을 사용한다.

Test Dataset은 하이퍼파라미터 선택에 사용하지 않는다.

Random Forest, XGBoost, LightGBM의 계산량이 과도한 경우 팀 합의 후 해당 모델에 대해 `RandomizedSearchCV(n_iter=30, random_state=42)`로 변경할 수 있다. 이 경우 Global과 모든 Local에서 해당 모델에 동일한 탐색 방법을 적용한다.

---

# 21. Class imbalance 처리

Global Dataset의 취업전환율은 약 26%로 class imbalance가 존재한다.

기본적으로 oversampling, undersampling, SMOTE 등 synthetic sample 생성은 사용하지 않는다.

대신 모델별 `class_weight` 또는 `scale_pos_weight`를 공통 하이퍼파라미터 후보로 탐색한다.

---

# 22. 평가 지표

주 지표는 **Positive class(취업전환=1)의 F1**이다.

보조 지표:

- Accuracy
- Precision
- Recall
- ROC-AUC
- Confusion Matrix

Threshold는 `0.5`로 고정한다. Test 성능을 본 뒤 threshold를 최적화하지 않는다.

---

# 23. Feature Importance

공통 비교 방법으로 **Permutation Importance**를 사용한다.

- 최종 held-out Test에서 계산
- `scoring = "f1"`
- `n_repeats = 20`
- `random_state = 42`
- 원 Feature 단위 비교

Logistic Regression coefficient와 Tree 계열 built-in importance는 보조자료로만 사용한다.

---

# 24. Global vs Local 결과 정리

각 직군에 대해 동일 Local Test Sample에서 다음을 기록한다.

- Global-on-Local F1
- Local F1
- `ΔF1`
- ΔAccuracy
- ΔPrecision
- ΔRecall
- ΔROC-AUC

Feature Importance는 Top 10을 중심으로 공통 Feature와 직군별 상대적 차이를 비교한다.

---

# 25. 불확실성 평가

SAMPID 단위 bootstrap 1,000회를 보조 분석으로 사용한다.

- bootstrap 단위: SAMPID
- 반복: 1,000
- seed: 42
- 95% CI 계산

특정 bootstrap 표본에 한 class만 존재해 평가 지표를 계산할 수 없는 경우 해당 반복은 제외한다.
