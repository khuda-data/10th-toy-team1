## 1. HTML 템플릿

### 1-0. 디자인 소스 = `26-2 10기/DESIGN-notion.md` (고정)

**새로 디자인하지 않는다.** 스타일 값은 전부 DESIGN-notion.md의 토큰에서 가져온다. 기존 해설(`EyesOnTheStreet_Quito_2025`)의 `<style>` 블록이 이 토큰을 CSS 변수로 옮겨둔 레퍼런스 구현이므로, 새 해설은 그 블록을 그대로 복사해 시작한다.

적용 규칙(어긴 적 있는 것만 명시):

| 항목 | 토큰 | 적용 위치 |
|---|---|---|
| 페이지 캔버스 | `canvas-soft` #f6f5f4 | `body` — 순백 전면 금지 |
| 카드 표면 | `surface` #ffffff + `hairline` 1px, 그림자 없음 | `.feature-card` |
| 카드 라운드/패딩 | `rounded.lg` 12px / `spacing.lg` 24px | `.feature-card`, `.an-card` |

### 배지 5종 (라벨/색상 고정, 이 중에서만 사용)

| 배지 클래스 | 라벨 | 용도 |
|---|---|---|
| `badge-teal` | TERMINOLOGY | 전문용어 정의 |
| `badge-sky` | CONTEXT | 이 문장이 논문 흐름에서 왜 여기 있는지 |
| `badge-orange` | MECHANISM | 구체적 절차·메커니즘·수식 |
| `badge-green` | LOGIC | 문장 간 논리 연결, 왜 이 결론이 나오는지 |
| `badge-purple` | IMPLICATION | 시사점 — 특히 우리 토이프로젝트 설계 함의 |

전체 세그먼트의 **30~40%에만** insights를 다는 것이 기본이다(핵심 발견·방법론적 선택·프로젝트 연결 지점만). 참가자 인용문은 뉘앙스를 살려 큰따옴표 + "(P번호)" 형식으로.

> **1호 해설에서의 이탈 기록**: `EyesOnTheStreet_Quito_2025`는 50개 세그먼트 중 38개(76%)에 insights가 달렸다. 원문 내부 불일치(로짓/프로빗 수식, 지표 번호·개수, 단위 표기, 오기로 보이는 부정문)가 많아 표시할 지점이 실제로 많았기 때문이다. 다음 논문이 평범하면 30~40%로 되돌린다.

**원문의 내부 불일치(수식·번호·단위·표본 수 오기 등)를 발견하면 감추지 말고 배지로 명시한다.** 재현을 시도할 때 그대로 따라 하면 안 되는 지점이기 때문이다.

## 2. 그림·표 삽입 — 필수, 생략 금지

원본의 Figure/Table을 전부 찾아 해당 그림/표를 **처음 언급하는 문단 직후**에 실제 이미지로 삽입한다. 텍스트 요약으로 대체하지 않는다.

### 절차 (PyMuPDF, 설치 확인: `python -c "import fitz"`)

1. `_fig_extract/` 스캐폴딩:
   - `render_pages.py` — 후보 페이지를 2.2배율 PNG로 렌더 → Read로 눈으로 위치(x/y 비율) 확인
   - `crop.py` — `page(1-indexed), x0,y0,x1,y1(0~1 비율), out.png` 를 받아 `fitz.Matrix(4,4)` 4배율 크롭
2. 렌더 → Read → 크롭 → Read 재확인. 캡션 전체와 그림 본체가 다 보이면 충분.
3. Python 스크립트로 **base64 인코딩 후 `<img src="data:image/png;base64,…">`로 직접 삽입** (외부 파일 경로 참조 금지 — Edge headless 변환 시 상대경로가 깨진다).
   - 삽입 위치: 그림을 처음 언급하는 `seg-anchor`의 고유 부분 문자열을 앵커로 `html.find(앵커)` → 그 feature-card가 끝나는 지점(다음 `<div class="feature-card">` / `<h2` / `<h3` 등장 위치) 바로 앞.
   - 삽입 블록:
     ```html
     <div class="fig-block"><img src="data:image/png;base64,…" style="width:100%;max-width:100%;border:1px solid var(--hairline);border-radius:8px;" alt="…">
     <div class="fig-caption"><b>Figure N: 영문 캡션</b><br>그림 N. 한국어 캡션.</div></div>
     ```
   - CSS에 `</style>` 직전 1회 추가:
     ```css
     .fig-block { margin: 18px 0 26px 0; text-align: center; }
     .fig-block img { display: inline-block; }
     .fig-caption { font-size: 13px; color: var(--ink-muted); margin-top: 8px; line-height: 1.5; text-align: left; max-width: 640px; margin-left: auto; margin-right: auto; }
     ```
4. 여러 그림은 **반드시 Python 스크립트로 일괄 삽입** (`insert_figs.py`). base64 문자열이 길어 Edit 도구 수동 호출은 비효율적이다.

## 3. PDF 변환 (Edge headless)

```powershell
$edge = "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"
$psi = New-Object System.Diagnostics.ProcessStartInfo
$psi.FileName = $edge
$psi.Arguments = "--headless=new --disable-gpu --no-sandbox --no-pdf-header-footer --print-to-pdf=`"<dst.pdf>`" `"file:///<src.html 슬래시 경로>`""
$psi.UseShellExecute = $false
$proc = [System.Diagnostics.Process]::Start($psi)
$proc.WaitForExit(120000)
```

- `--headless`(구식)는 파일이 안 만들어질 때가 있으므로 **`--headless=new`** 를 쓴다.
- 머리말/꼬리말(날짜·제목·file:/// 경로·페이지번호) 제거 플래그는 이 환경의 Edge에서 **`--no-pdf-header-footer`** 다. 구식 `--print-to-pdf-no-header`는 무시되어 헤더가 그대로 찍힌다 (2026-07-29 확인).
- 변환 후 크기 확인 + PyMuPDF로 몇 페이지 렌더링해 스팟체크. `d[0].get_text()`에 `file:///`가 있으면 헤더 제거가 안 된 것이다.

## 4. 병렬 작업 시 주의 — Fork 폭주 방지

논문이 길면 섹션을 나눠 fork를 병렬로 띄우되:

- 각 fork 프롬프트에 **"네 담당 구간의 순수 HTML 조각만 반환하고, 파일을 직접 쓰거나 변환하지 마라"** 를 명시한다.
- **조립은 메인 turn에서 Write로 한 번만** 수행한다.
- fork 결과가 담당 범위를 넘어오면 파일 무결성부터 검증(섹션 헤더 목록, `grep -c`)한 뒤 취사선택한다.

## 5. 토이프로젝트 매핑 섹션

전체 번역이 끝난 뒤 **메인 turn이 직접** 6~7개 카드로 작성한다(논문 전체를 조망해야 좋은 매핑이 나오므로 fork에 위임하지 않는다).

각 카드: 이 논문의 특정 발견/설계 선택 → 우리 토이프로젝트에 주는 구체적 시사점.

- 주제가 확정되기 전에는 **"적용 후보"** 로 쓴다. 아직 정해지지 않은 것을 정해진 것처럼 쓰지 않는다.
- 과장 금지. 실측 결과가 아니라 저자의 해석·한계인 경우 그 사실을 명시한다.
- 데이터 대응(해외 데이터 → 국내 공공데이터)을 적을 때는 **실제로 존재를 확인한 출처만** 적고, 확인 못 한 것은 "확인 필요"로 남긴다.
