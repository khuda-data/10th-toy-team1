# data — 프로젝트 데이터

**왜 raw와 result를 나눴나**: 원본과 가공물이 한곳에 섞이면 "이 파일이 받은 그대로인지 누가 손댄 건지"를 알 수 없게 되고, 그 순간 분석의 재현이 불가능해진다. 원본은 얼려두고(raw), 가공물은 언제든 코드로 다시 만들 수 있게(result) 분리했다.

| 폴더 | 무엇 | 규칙 |
|---|---|---|
| `raw/` | 내려받은 그대로의 원본 데이터 | **절대 수정 금지.** 파일을 추가하면 아래 "출처 기록" 표에 한 줄 추가 |
| `result/` | **팀 공용·최종 결과물** — 통합 코드(`code/`)가 만든 것만 | 코드로 **다시 만들 수 있어야** 한다. **개인 중간 산출물은 여기 말고 자기 `sandbox/<git아이디>/`에** |

## 형식 약속

여러 명이 주고받는 데이터의 **파일 포맷·컬럼명·타입·단위**는 `plan/details/06-인터페이스.md`에 기록된 약속을 따른다. 약속에 없는 형식이 필요하면 먼저 거기에 추가할 것.

## 용량 규칙

- **10MB가 넘는 파일은 커밋하지 않는다** (GitHub 개별 파일 제한 100MB, 레포가 무거워지면 clone이 느려진다).
- 큰 원본 데이터는 커밋 대신 아래 표에 **다운로드 출처와 방법**을 적어서, 누구든 같은 데이터를 받을 수 있게 한다.

## 출처 기록 (raw 데이터를 추가할 때마다 한 줄씩)

| 파일/폴더 | 출처 (URL) | 받은 날짜 | 받은 사람 | 비고 |
|---|---|---|---|---|
| (예시) `raw/seoul_pop.csv` | data.seoul.go.kr/... | 2026-08-XX | NaHoYeol | 생활인구, 커밋됨 |
